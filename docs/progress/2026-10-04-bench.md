# Bench session, 2026-10-04

First hardware session with the M5Stack Dial as the thermostat brain.
Result: `esphome/hestian-dial-conventional.yaml` works end to end on the
bench (nothing connected to the HVAC).

## Verified

- SCD40 reports temperature, humidity and CO2 (address 0x62)
- Heat/Cool picks heating or cooling on its own
- 5 minute minimum run and off times protect the compressor
- `startup_delay: true` holds off calls for 5 minutes after a reboot
- Interlock keeps heat and cool relays from running together
- Thermostat keeps working if HA or WiFi is down (`reboot_timeout: 0s`)
- UI: mode-coloured ring, running indicator, knob adjusts the active
  setpoint in Heat or Cool, press for a menu, brightness control

## Gotchas found

- Grove wire colours did not match the expected GPIOs on either port;
  PORT.A is SDA GPIO15 / SCL GPIO13. Confirm pins in software.
- Grove ports supply 5 V only; a buck to 3.3 V powers the I2C devices.
- A purple 6-pin BME280 is 3.3 V only. Replaced by an SCD40.
- First SCD40 board had no I2C pull-ups ("SCL is held low", both lines 0 V).
- Heat/Cool mode only appears when `heat_cool_mode:` is defined.
- Min off timers do not start at boot unless `startup_delay: true` is set.
- Switching to Off stops a call immediately; min run only applies when the
  thermostat ends a cycle itself.
- Relay jumpers on H: OFF is a solid 0 V and relays stay off during boot.
- The SCD40 read about 3 to 4 °F high next to the Dial and buck.

## Afterwards

The vault notes confirmed the system is a heat pump (Y, O/B, W2, G), so the
two-relay W/Y layout must not be wired to it. `hestian-dial-heatpump.yaml`
carries the same build onto four relays through an MCP23017 (a PCF8574 was
rejected because it cannot drive high and would need 5 V logic).
